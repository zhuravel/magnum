# The fix loop Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `magnum fix <pr>` (board key `f`) starts a loop in which a fixer agent, as the operator, fixes magnum's findings on the operator's own PR in the PR's slot, pushes, and magnum re-reviews, until a review posts no findings, the fixer needs the operator, or a cap is reached.

**Architecture:** A new role class (`fix = true`, built-in `claude-fix`) that never joins a round; an engine job (`internal/engine/fix.go`) that holds the PR with a reservation and a registry row, runs the fixer as one run (`NewRun` kind `fix` + `Submit`), reads a three-section report, resyncs the slot and forces the re-review; a post-round hook that continues or ends the loop; a bundled skill (`skills/magnum-fix/SKILL.md`) and prompt (`prompts/fix.md`) handled like the judge's; a CLI command and a board key on the existing request and action paths.

**Tech Stack:** Go 1.27, SQLite registry (migration 0025), Bubble Tea v2 screens, cobra CLI, herdr panes through `internal/agents`.

**Spec:** docs/superpowers/specs/2026-10-10-fix-loop-design.md

## Global Constraints

- The repository is public: no private organization, repository or person in tracked files, tests, docs or commit messages; logins only `zhuravel` or placeholders (`alice`, `rev-ann`); orgs `talkable` or `example` in examples (AGENTS.md).
- Tests are hermetic: `storetest.Open`, fakes for git, gh, herdr; never `bin/magnum`, git, herdr or launchctl against real directories or sockets from a test or an agent task. `storetest.Serial(t)` before `t.Setenv` or a package-variable swap. Round scripts report with `t.Errorf`, never `t.Fatal`.
- Gate from a worktree: `MISE_EXEC_AUTO_INSTALL=false MISE_AUTO_INSTALL=false mise -C <checkout> exec -- sh -c "cd <worktree> && go test -count=1 -race ./internal/<pkg>/"`, then `mise -C <checkout> exec -- make -C <worktree> test`. `golangci-lint run --new-from-rev=master ./...` must report 0 issues on the lines you touched. `make api-doc` after exported changes.
- Migration 0025 lands in this branch: never run `make build` in the main checkout or `bin/magnum` while it is unlanded; the daemon restart at the end is `bin/magnum daemon-restart --drain`.
- No new dependencies; every commit message is one paragraph ending in "No new dependencies.".
- Every destructive step is idempotent or guarded, writes `begin`/`ok`/`fail` events and re-runs its guard when resumed; state transitions are compare-and-set with explicit from-states; logs and events never carry tokens or PR text.
- Every action key asks y/N and only `y` confirms; the README describes every new key, command and config key; a behaviour change gets a `docs/DECISIONS.md` entry appended at the end of its section (never inside `## Learned rules`).
- Prompts carry URLs, SHAs and paths, never PR text. The fixer never writes a `magnum:run=` marker on GitHub.

## Review Focus

- A push by the operator while the fixer works: the fixer's push is not a fast-forward and fails; the report must say so and the job must end as failed, with the slot resynced to the old head. Pinned to Task 6's `TestAFixWhosePushFailedEndsAsFailed`.
- A fixer that committed in the slot but pushed nothing: the slot's HEAD drifts from `checked_out_sha`; settle must switch back to the old head or the next round's guard holds the slot. Pinned to Task 5's `TestResyncSwitchesDetachedAndRecordsTheHead` and Task 6's `TestAFixThatPushedNothingResyncsTheSlot`.
- A report with the marker but missing sections, or a stale marker: must count as failed, never as "nothing pushed". Pinned to Task 4's `TestParseFixReportRefusesAPartialReport`.
- A watch whose posting identity is the operator's own gh identity: the fixer's replies then come from the reviewer's login and the re-review's thread summary leaves own replies out. The README must say to post as an App identity when the fix loop is on, and the config validation must warn. Pinned to Task 1's `TestValidateFixRoleWarnsWhenThePosterIsTheFixer`.
- `autofix = "own"` on a PR whose head changed between the review and the hook: the job's guard refuses (head not equal to the reviewed head) and the loop does not start. Pinned to Task 7's `TestAutofixSkipsAHeadThatMovedSinceTheReview`.
